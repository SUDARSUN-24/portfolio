01 — Full-stack web app · university project

Siam Library Book Preview

Students read a short preview of any library book, see if it is on the shelf and exactly where, then borrow it at the counter.

Tests

Staff area
Add books, upload page photos from a phone, mark books borrowed or returned, print QR stickers

Visit site: Siam Library Book Preview ↗ Code: Siam Library on GitHub ↗

Case studyProblem, decision, trade-off, result
Problem
Students can't judge a library book from its title, and can't tell if it is on the shelf until they walk there.
Decision
Add a "look inside" preview of 5–10 pages, live availability and the exact shelf and row, plus a QR code on every book and shelf that links the physical library to the website.
Trade-off
A preview of 5–10 pages keeps the upload work small for staff, but it is a teaser, not the whole book, and borrowing still happens at the counter.
Result
Live on Vercel with a Neon PostgreSQL database and private photo storage, in Thai and English, with a Docker setup ready for a university server.
02 — Full-stack web app · Agile course project

CanteenFlow Campus food pre-order

Siam University students order from a campus stall, pick a 15-minute pickup slot and follow the order live. Stall staff accept, reject and complete orders on their own page.

Tests
61 automated tests, including orders and cancels that arrive at the same moment
Vendor side
Sign-in per stall, Accept or Reject with a reason, Ready, Collected, No-show and a Sold Out switch. Each stall sees only its own orders.
Rules
Slot capacity, active orders per student, a No-show limit and a cancel window, kept in one config file and checked on the server
Map
3D campus map drawn in SVG from OpenStreetMap building outlines, without a map library
Role
Agile course project (team Dagabaaz Re). I built the app: design, front end, back end, database, tests
Built with
  • Node.js
  • Express
  • SQLite
  • Turso
  • JavaScript
  • SVG
  • Vercel

Visit site: CanteenFlow ↗ Code: CanteenFlow on GitHub ↗

Case studyProblem, decision, trade-off, result
Problem
At lunchtime students queue at every campus stall, and stalls can't plan what to cook. A pre-order app must also stop one student from taking many pickup places or leaving food uncollected.
Decision
Pickup slots with a fixed capacity, a limit on active orders per student, a No-show limit, and cancelling only until the stall accepts. The server checks each rule in the same database transaction as the change, so two requests at once can't overbook a slot.
Trade-off
Sign-in is a demo: any 10-digit student ID, and a public PIN for each stall. That keeps the course demo simple, but real university accounts are needed before real use. The rule numbers are proposals waiting for the customer's decision.
Result
Two sprints of user stories with acceptance criteria, live on Vercel with a Turso database, and 61 tests that run in about a second.

Visit site: Resonance ↗ Code: Resonance on GitHub ↗

Case studyProblem, decision, trade-off, result
Problem
Text-to-speech that works in any browser, with no install, no account and no paid API.
Decision
Use the browser's built-in speech voices, plus an optional open-source voice (Kokoro) that runs on the device in a Web Worker, instead of a paid cloud service.
Trade-off
Built-in voices sound different on every device and operating system, so quality is not the same for everyone. The on-device Kokoro voice gives one consistent sound, at the cost of a larger first download.
Result
Free to run, works offline after the first visit, and a deploy only goes out when all 116 tests pass.

Visit site: Velonix Customs ↗ Code: Velonix Customs on GitHub ↗

Case studyProblem, decision, trade-off, result
Problem
Show five vehicles in 3D and let people hear the engine, without making the page slow.
Decision
One shared Three.js scene for the home page and the configurator, and engine sound generated with the Web Audio API instead of recorded files.
Trade-off
Engine sound made in code is tiny and loads instantly, but it is a synthesised approximation, not a recording of a real engine.
Result
No audio files to download, and browser tests confirm the home page still works when 3D (WebGL) is unavailable.
